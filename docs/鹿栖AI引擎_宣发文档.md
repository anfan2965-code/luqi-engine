# 鹿栖 AI 引擎 (LuqiAI Engine)

## 当 AI 不再只是回答问题，而是真正「活着」

---

### 一、我们看到了什么问题

当前对话 AI 存在三个根本性缺陷：

**缺陷一：角色是面具，不是人格。** 现有的角色扮演系统通过 system prompt 注入人设，但模型并不真正「拥有」这个人格——它只是在模仿。一旦对话深入，角色行为就会漂移、崩塌、甚至自相矛盾。

**缺陷二：情感是标签，不是体验。** 情感标注系统将情绪简化为离散标签（开心/悲伤/愤怒），但真实的人类情感是连续的、混沌的、随情境动态演化的。标签式情感无法产生真正的共情对话。

**缺陷三：智能依赖云端，离线即死亡。** 几乎所有高质量对话 AI 都依赖云端大模型。一旦断网，角色就变成一具空壳。而移动端部署的本地模型又因体积和算力限制，无法承载复杂人格。

这三个缺陷指向同一个结论：**我们需要一种全新的引擎架构，让人格内化、情感动态化、智能本地化。**

---

### 二、鹿栖引擎是什么

鹿栖 AI 引擎是一个面向**移动端离线部署**的**拟人化对话引擎**，其核心目标是让 AI 角色具备：

- **内化的人格** — 不是 prompt 模拟，而是 OCEAN 五维人格（0-100分制）+ 17 维欲望向量驱动的行为一致性
- **动态的情感** — 不是标签切换，而是 PAD 三维空间 + 七情权重矩阵 + Lorenz 混沌吸引子驱动的情感连续演化
- **分级的智能** — 不是全靠云端，而是三级意图路由（SIMPLE/MODERATE/COMPLEX）实现成本/质量/延迟的最优平衡
- **协作的表达** — 不是单一模型生成，而是四智能体协作（Dialogue→SupremeCourt→Critic→Novelist→Atmosphere→Voice→Assemble）

一句话定义：**鹿栖引擎让 AI 角色在手机端离线运行时，依然拥有稳定人格、动态情感和智能对话能力。**

### 三、核心架构

#### 3.1 四智能体协作数据流

```
用户输入
    │
    ▼
┌─────────────────┐
│  DialogueAgent   │  意图识别 + 情感判断 + 行动提议
│  (对话智能体)     │  输出: CanonicalIR {intent, emotion_delta, action, tone}
└──────┬──────────┘
       ▼
┌─────────────────┐
│ AlgorithmSupremeCourt │  纯算法一致性校验
│  (最高法院)       │  校验: intent/emotion/action/tone 合理性
└──────┬──────────┘
       ▼
┌─────────────────┐
│  CriticAgent     │  对话质量审查 ★本地LLM快速路径可跳过
│  (审查智能体)     │  输出: ACCEPT / MINOR_FIX / MAJOR_REWRITE / REJECT / REVIEW
└──────┬──────────┘
       ▼
┌────────────────┐     ┌─────────────────┐
│ NovelistAgent   │     │ AtmosphereAgent  │
│ (小说家智能体)   │     │ (氛围智能体)      │
│ 叙事增量生成     │     │ 环境氛围渲染      │
│ 新事实/剧情推进  │     │ 天气/光线/声音    │
└──────┬─────────┘     └──────┬──────────┘
       │                       │
       ▼                       ▼
┌─────────────────┐
│  VoiceRenderer   │  语音风格渲染（内心独白/语气词）
└──────┬──────────┘
       ▼
┌─────────────────┐
│ OutputAssembler  │  最终响应组装
└──────┬──────────┘
       ▼
   用户收到回复
```

#### 3.2 三级意图路由

```
用户输入
    │
    ▼
┌──────────────────┐
│  IntentClassifier │  规则链 + 关键词库 + 长度分析
│  意图分类器        │  32个情感词 / 16个叙事词 / 7个多角色指示词
└──────┬───────────┘
       │
       ├── SIMPLE (≤20字, 日常寒暄)
       │       └──→ LocalLLMAdapter (Qwen2.5-0.5B GGUF, 离线运行)
       │
       ├── MODERATE (20-100字, 含情感词)
       │       └──→ LocalLLMAdapter (Qwen2.5-0.5B GGUF, 离线运行)
       │
       └── COMPLEX (>100字, 多角色/叙事/世界观)
               └──→ 云端 LLM API (DeepSeek 等)
```

**为什么是三级？** 因为 80% 的日常对话是 MODERATE 级别——用户在表达情感、寻求陪伴时，不需要千亿参数模型的推理能力，一个经过情感对话特化训练的 0.5B 模型就够了。这意味着 **80% 的对话零云端成本**。

#### 3.3 人格内化系统

传统方案：`system prompt = "你是一个温柔的女孩，名叫小雪"`

鹿栖方案：

```
OCEAN 人格向量:  [开放性=90, 尽责性=70, 外向性=25, 宜人性=65, 神经质=45]
                     ↓ ocean_to_pad_baseline() 映射
PAD 情感基线:     [愉悦度=+0.03, 激活度=-0.06, 支配度=-0.08]
                     ↓ StateRenderer 压缩
System Prompt:   [角色]小雪 [性格]开放/内向/温和/敏感 [情绪]悲伤0.7 [场景]教室
                     ↓ 注入
Qwen2.5-0.5B:    ≤300 token 的结构化 system prompt
```

**关键差异**：人格不是一段文字描述，而是一组可计算的数值向量。基于 Mehrabian (1996) 的实证相关系数，15 个权重将 OCEAN 映射到 PAD 三维空间：

| PAD轴 | 最强影响因子 | 权重 |
|------|------------|------|
| 愉悦度 | 宜人性(A) | +0.25 |
| 激活度 | 神经质(N) | +0.20 |
| 支配感 | 外向性(E) | +0.30 |

#### 3.4 混沌情感引擎

```
Lorenz 吸引子 (σ=10, ρ=28, β=8/3)
    │  四阶 Runge-Kutta 求解 (dt=0.01)
    │  归一化到 [0,1]
    ▼
三维混沌轨迹 (x, y, z)
    │  耦合系数 0.1 × 衰减系数 0.95
    ▼
PAD 情感空间 (愉悦度/激活度/支配度)
    │  钳位到 [-1, 1]
    ▼
七情权重矩阵 (喜怒哀惧爱恶欲)
    │  dominant_emotion()
    ▼
对话输出: "（内心：有些不安，但还是微笑着说）"
```

**为什么用 Lorenz 混沌？** 因为人类情感的本质特征是**确定性中的不可预测性**——同样的刺激在不同时刻可能引发不同反应，但整体情感轨迹又是有结构的。Lorenz 吸引子恰好具备这一特性：短期可预测、长期混沌、对初始条件敏感。这不是随机噪声，而是**有结构的情感波动**。

**七情→PAD固定向量**（全部基于代码实际值）：

| 情绪 | P | A | D |
|------|---|---|---|
| 喜 | +0.6 | +0.5 | +0.3 |
| 怒 | -0.6 | +0.7 | +0.4 |
| 悲 | -0.7 | -0.3 | -0.4 |
| 恐 | -0.7 | +0.5 | -0.5 |
| 爱 | +0.5 | +0.3 | +0.2 |
| 厌 | -0.5 | +0.3 | +0.1 |
| 欲 | +0.3 | +0.6 | +0.2 |

**阻尼更新公式**：`新值 = clamp(旧值 × 0.85 + 事件冲击 × scale)`，结果钳制在[-1,+1]范围内，模拟人类情绪惯性。

#### 3.5 四级降级容错

```
NORMAL ──3次失败──→ DEGRADED ──5次失败──→ SEVERELY_DEGRADED ──10次失败──→ OFFLINE
   ↑                   │                        │                          │
   │  2次连续成功       │ 优先使用本地LLM         │ 模板响应                  │ 30秒探测
   └───────────────────┘                        │                          │
                                    可降级使用本地LLM            允许一次探测请求
```

**核心原则**：引擎永远不会完全停止响应。即使云端完全不可用，本地 0.5B 模型依然能维持基础对话能力。

#### 3.6 认知记忆系统

引擎包含两套记忆系统：

**简单记忆（CharacterEntity 使用）— 3 层**：

| 层级 | 用途 | 淘汰策略 |
|------|------|----------|
| 短期记忆 | 最近发生的事 | LRU |
| 长期记忆 | 反复回忆的重要事 | 低速衰减淘汰 |
| 情感记忆 | 强烈情绪体验的事 | 中速衰减淘汰 |

**认知记忆（CognitiveMemoryStore）— 6 层**：

| 层级 | 用途 |
|------|------|
| 感觉记忆 | 原始感觉输入 |
| 工作记忆 | 当前活跃处理的信息 |
| 短期记忆 | 近期事件 |
| 长期记忆 | 反复访问的重要事件 |
| 情感记忆 | 强烈情绪体验 |
| 程序记忆 | 技能和习惯性知识 |

**记忆晋升机制**：
- 反复访问 ≥3 次 → 晋升为长期记忆
- 情感效价绝对值 ≥0.7 → 晋升为情感记忆

#### 3.7 关系链建模

每对角色间的关系通过**物理弹簧模型**演化：

```
关系势能值 ∈ [-1, +1]
    │  每次交互产生冲量(delta)
    ▼
速度 += delta; 位置 += velocity;  速度 *= (1 - 0.01)
```

三个指标合成最终感知分：`感知分 = 归一化势能 × 平均保真度 × (1 - 平均熵值)`

### 四、技术亮点

#### 4.1 零硬编码架构

所有数值参数集中在 `EngineConfig` 的 12 个 dataclass 中，支持外部加载。代码中不存在任何魔法数字——阈值、权重、维度、容量全部可配置、可调优、可复现。

#### 4.2 确定性随机

基于 **PCG-XSH-RR** 变体的确定性随机数生成器（64位状态，16字节），支持：
- 五级种子层级派生（世界/阵营/角色/场景/事件），基于 SHA-256
- 多独立流隔离（SeededRNGManager）
- Marsaglia 极坐标法正态采样（无三角函数依赖）
- 状态保存与恢复

同一颗种子，永远产生相同的叙事走向。

#### 4.3 概率分布工具包

自研 `DistributionToolkit`，不依赖 numpy/scipy，实现 5 种分布采样（正态/指数/帕累托/贝塔/三角），内置 Lanczos Gamma 近似和 Marsaglia-Tsang 采样算法。

#### 4.4 模块化架构

采用模块化继承 + 路由分发模式：

| 组件 | 职责 | 行数 |
|------|------|------|
| EngineCore | 初始化、配置、生命周期管理 | ~300行 |
| EngineChat | 对话功能、流式对话 | ~400行 |
| EngineWorld | 世界观、场景、角色创建 | ~150行 |
| ChatOrchestrator | chat() 6阶段流水线编排 | ~500行 |
| EngineInitializer | initialize() 7阶段初始化编排 | ~300行 |
| CharacterExtractor | 角色信息统一提取 | ~150行 |

#### 4.5 事件驱动架构

EventBus 中央事件总线，支持同步/异步处理器共存、按事件类型路由、优先级排序、历史记录与回放。

#### 4.6 17 维欲望向量

从生理需求到超越需求，情感变化自动触发欲望更新，饱和度机制控制满足感衰减，驱动链排序决定行为优先级。

### 六、市场定位

#### 目标场景

- **移动端 AI 伴侣** — 离线可用、低功耗、低延迟的拟人化对话
- **游戏 NPC 人格引擎** — 让 NPC 拥有独立人格和动态情感，而非脚本树
- **数字人/虚拟偶像** — 人格一致性 + 情感表达力 + 长期记忆
- **心理健康辅助** — 共情对话 + 情感追踪 + 认知记忆
