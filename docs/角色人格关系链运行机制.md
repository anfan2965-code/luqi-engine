# LuqiAI 引擎 · 角色/人格/关系链 运行机制

## 一、角色是怎么"出生"的

角色不是凭空产生的，而是通过 NPCFactory（角色工厂）按模板制造的。工厂目前有 6 种预设原型：

| 原型 | 定位 | 核心人格倾向 |
|------|------|-------------|
| 守卫(guard) | 秩序维护者 | 尽责85、外向30、宜人40 |
| 商人(merchant) | 交易中介 | 外向75、宜人70、神经40 |
| 学者(scholar) | 知识追求者 | 开放90、尽责70、外向25 |
| 战士(warrior) | 战斗人员 | 外向65、尽责55、宜人35 |
| 法师(mage) | 奥术使用者 | 开放95、尽责75、外向20 |
| 刺客(assassin) | 隐秘行动者 | 尽责80、外向15、宜人20 |

每个模板出厂时自带两件事：

1. **OCEAN 五维人格分数**（0-100 分制）— 这是角色的"性格基因"
2. **分层动机列表** — 从底层生存需求到顶层自我实现，每个原型有不同的动机优先级

工厂造出角色后，交给 CharacterManager（角色管理器）统一管理生命周期：注册、存档、一致性校验、序列化/反序列化。

## 二、人格系统怎么运转

### 2.1 OCEAN 大五模型 — 角色的"性格底色"

人格用五个维度量化，每个维度 0-100 分：

- **O**（开放性 Openness）：有多愿意尝试新事物
- **C**（尽责性 Conscientiousness）：有多自律、有条理
- **E**（外向性 Extraversion）：有多喜欢社交互动
- **A**（宜人性 Agreeableness）：有多合作、多顺从
- **N**（神经质 Neuroticism）：情绪有多不稳定

这五个数字不是摆设，它们**直接参与每一次决策**。当角色需要选择做什么动作时，`influence_decision()` 会根据当前情境，用不同维度对不同类型的决策施加权重修正。比如：

- 外向高的人 → 社交类行动得分被放大
- 神经质高的人 → 危险规避类行动得分被放大
- 宜人高的人 → 冲突类行动得分被缩小

### 2.2 人格不是死的 — 有漂移机制

PersonalityAdapter 允许人格随经历缓慢漂移。角色经历了重大事件后，其 OCEAN 分数会朝着某个目标值微量偏移。这不是突变，而是一个渐进过程，由经验强度控制漂移速度。

### 2.3 OCEAN 决定情感基线

人格还负责一件事：**决定角色的情绪起点**。通过 `ocean_to_pad_baseline()` 函数，OCEAN 五个分数会被映射成一个 PAD 三维情感坐标（愉悦度/激活度/支配度），这就是角色在没有任何外部刺激时的"默认心情"。

映射关系基于心理学实证研究（Mehrabian 1996），例如：

- 外向高 → 愉悦度高（+0.21 权重）、支配度高（+0.30 权重）
- 神经质高 → 愉悦度低（-0.26 权重）、激活度高（+0.20 权重）

完整的 5×3 权重矩阵（5 个 OCEAN 维度 × 3 个 PAD 维度）共 15 个权重，全部基于实证数据。

## 三、情感系统怎么运转

### 3.1 PAD 三维空间

所有情感最终都归约到三个轴上：

| 轴 | 含义 | 范围 |
|----|------|------|
| Pleasure（愉悦度） | 正面↔负面感受 | -1 到 +1 |
| Arousal（激活度） | 平静↔激动 | -1 到 +1 |
| Dominance（支配感） | 被动↔掌控 | -1 到 +1 |

### 3.2 七情到 PAD 的映射

引擎定义了七种基础情绪，每种都有固定的 PAD 向量：

| 情绪 | P | A | D | 直觉理解 |
|------|---|---|---|----------|
| 喜(Joy) | +0.6 | +0.5 | +0.3 | 开心、有活力、略带主动 |
| 怒(Anger) | -0.6 | +0.7 | +0.4 | 不爽、很激动、想对抗 |
| 悲(Sorrow) | -0.7 | -0.3 | -0.4 | 消沉、低能量、被动 |
| 恐(Fear) | -0.7 | +0.5 | -0.5 | 极度不安、紧张、逃避 |
| 爱(Love) | +0.5 | +0.3 | +0.2 | 温暖、平和、轻微主动 |
| 厌(Disgust) | -0.5 | +0.3 | +0.1 | 不适、有些激动、略抗拒 |
| 欲(Desire) | +0.3 | +0.6 | +0.2 | 期待、兴奋、有点主动 |

### 3.3 情感的动态更新

当外部事件发生时，情感不会直接跳变，而是经过一个**阻尼更新公式**：

```
新值 = clamp((旧值 × 阻尼系数) + (事件冲击 × 缩放因子))
```

阻尼系数默认 0.85，意味着每次更新时旧状态保留 85%，新冲击只贡献 15%。`clamp` 将结果钳制在 [-1, +1] 范围内，防止多轮对话后PAD值溢出。这让情感变化是**平滑过渡**而不是瞬间跳变，模拟真实人类情绪的惯性。

如果没有新事件持续输入，情感会自动衰减回零点附近（中性状态），衰减速度同样由阻尼系数控制。

### 3.4 扩展 PAD — 复合情感

ExtendedPAD 在基础 PAD 之上增加了七情之间的**交叉影响矩阵**。一种情绪的强度会通过权重矩阵影响其他情绪的 PAD 贡献。比如"怒"很强时，它不仅直接推高 A 轴，还会通过交叉权重间接增强或抑制其他情绪的表现力。

## 四、关系链是怎么构建的

这是最关键的部分——关系不是预先写死的，而是在交互中**动态演化**出来的。

### 4.1 关系势能（RelationshipPotential）

每对角色之间都有一个**关系势能值**，范围 -1 到 +1：

- 负值 = 敌对/排斥关系
- 零 = 中立/无特殊关系
- 正值 = 友好/亲近关系

这个值的变化遵循**物理弹簧模型**：

- 每次交互产生一个 delta（正或负的冲量）
- 势能值加上速度增量，速度本身也有惯性
- 同时存在自然衰减（像弹簧慢慢回到平衡位置）

这意味着关系是**有惯性的**——一次友好交互不会立刻让陌生人变好友，多次积累才会；一次冲突也不会立刻让朋友反目，除非冲突持续发生。

### 4.2 语境保真度（ContextFidelity）

每个角色还有一个**语境保真度**，衡量该角色对当前场景理解的准确程度。初始值为 1.0（完全保真），但各种"扭曲源"会降低它：

- 信息不完整
- 被欺骗/误导
- 记忆模糊

每种扭曲源独立记录，可以单独消除。保真度低意味着角色对局势的理解有偏差，会影响它的决策质量。

### 4.3 干预熵值（InterventionEntropy）

记录一个角色被外部力量干预的累积程度。每次干预都会增加熵值，熵值越高表示该角色的自主性越低。熵值会缓慢自然衰减，但如果频繁干预就会持续升高。

### 4.4 综合感知分

三个指标合成一个最终的**感知分**（0-1）：

```
感知分 = 归一化势能 × 平均保真度 × (1 - 平均熵值)
```

这个分数决定了两个角色之间的互动质量和可信度。高分 = 关系良好 + 双方都清楚状况 + 没有被过度操控。

### 4.5 记忆系统 — 关系的载体

关系演化的历史记录在记忆系统中。引擎包含两套记忆系统：

**简单记忆系统**（CharacterEntity 使用）— 3 层结构：

| 层级 | 容量 | 用途 | 淘汰策略 |
|------|------|------|----------|
| 短期记忆(SHORT_TERM) | 较小 | 最近发生的事 | LRU（最近最少使用） |
| 长期记忆(LONG_TERM) | 较大 | 反复回忆的重要事 | 低速衰减淘汰 |
| 情感记忆(EMOTIONAL) | 中等 | 强烈情绪体验的事 | 中速衰减淘汰 |

**认知记忆系统**（CognitiveMemoryStore）— 6 层结构：

| 层级 | 用途 |
|------|------|
| 感觉记忆(SENSORY) | 原始感觉输入，极短保留 |
| 工作记忆(WORKING) | 当前活跃处理的信息 |
| 短期记忆(SHORT_TERM) | 近期事件 |
| 长期记忆(LONG_TERM) | 反复访问的重要事件 |
| 情感记忆(EMOTIONAL) | 强烈情绪体验 |
| 程序记忆(PROCEDURAL) | 技能和习惯性知识 |

每条记忆是一个 **5Ws 条目**：Who（和谁）、What（发生了什么）、When（何时）、Where（何地）、Why（为什么），外加情感效价（正面/负面）和重要程度。

**记忆晋升机制**：短期记忆中的条目如果被反复访问（≥3 次），会自动晋升为长期记忆；如果情感效价很强（绝对值 ≥ 0.7），则晋升为情感记忆。这模拟了人类"印象深刻的事记得更久"的心理机制。

检索时按相关性排序，考虑文本相似度 + 时间衰减 + 重要度加权。

## 五、完整决策循环 — 所有子系统如何协同工作

当一个外部事件到来时（比如玩家对角色说话），以下流程依次执行：

```
① 事件接收（on_event）
    ↓
② 感知层：识别事件类型、涉及对象、环境信息
    ↓
③ 情感响应：PAD 状态根据事件性质即时更新
    ↓
④ 欲望驱动：情感变化触发欲望向量更新（DesireEngine）
    ↓
⑤ 动机评估（MotivationEngine）：三层动机加权排序
    ├─ 第一层：生存需求（最基础）
    ├─ 第二层：社会需求（关系、归属）
    └─ 第三层：自我实现（最高级）
    ↓
⑥ GOAP 规划：根据当前最高优先动机，规划可执行的行动计划
    ↓
⑦ 效用评分（UtilityAI）：每个候选行动打分
    ↓
⑧ 人格修正：OCEAN 分数调整各行动的效用权重
    ↓
⑨ 情感修正：当前 PAD 状态进一步微调行动选择
    ↓
⑩ CEM 熵扰动（CEMPlanner）：引入可控随机性，
    让行为不完全 deterministic（温度自适应）
    ↓
⑪ 执行选定的行动
    ↓
⑫ 一致性验证：检查结果是否与人格(40%)+情感(30%)+记忆(30%)
    的综合预期一致（阈值 ≥95%）
    └─ 如果不一致 → 回滚或触发重新规划
```

### 各子系统的数据流向：

```
外部事件 ──→ PAD情感更新 ──→ DesireEngine欲望更新
                                    ↓
                          MotivationEngine动机排序
                                    ↓
                            GOAP规划候选行动
                                    ↓
                        UtilityAI + OCEAN人格加权
                                    ↓
                      CEM熵扰动（自适应温度选择）
                                    ↓
                          最终行动执行
                                    ↓
              MemoryStore记录事件 + SocialPerception更新关系
```

## 六、四智能体协作架构

角色内部决策循环的输出，会进入引擎的**四智能体协作数据流**，将算法决策转化为自然语言对话：

```
Dialogue → SupremeCourt → Critic → Novelist → Atmosphere → Voice → Assemble
```

| 阶段 | 智能体/组件 | 职责 |
|------|------------|------|
| Phase 1 | DialogueAgent | 生成 CanonicalIR（意图+情感+行动） |
| Phase 2 | AlgorithmSupremeCourt | 校验 CanonicalIR 的一致性和合理性 |
| Phase 3 | CriticAgent | 审查对话质量（本地LLM快速路径可跳过） |
| Phase 4 | NovelistAgent + AtmosphereAgent | 叙事增量 + 氛围渲染 |
| Phase 5 | VoiceRenderer | 语音渲染 |
| Phase 6 | OutputAssembler | 组装最终输出 |

这套架构的设计理念是：**算法层保证逻辑一致性，语言层保证表达自然性**。

## 七、核心设计理念

**人格是静态底色，情感是动态响应，关系是交互产物，三者通过统一的决策循环实时联动。**

- 人格（OCEAN）提供决策的长期倾向性
- 情感（PAD）提供对即时情境的快速响应
- 关系（SocialPerception）提供交互历史的累积效应
- 记忆（MemoryStore）提供经验的持久化载体
- 四智能体协作将算法决策转化为自然对话
